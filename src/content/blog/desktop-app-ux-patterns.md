Desktop software is judged by how well it supports sustained work. The best interfaces make important actions discoverable, repetitive actions fast and recovery unsurprising.

## Use platform habits wisely

Respect expected menus, window behaviour, keyboard shortcuts, file pickers and permission language. A shared product identity can coexist with platform-specific details that reduce cognitive load.

## Make dense work legible

Use hierarchy, grouping, persistent context and clear selection states. Tables, inspectors and side panels should expose relationships without turning every action into a modal dialog.

## Design files and updates

Explain where work is saved, what is local and what is synced. Make backups, updates, migration and failure recovery visible. A desktop app that loses a file loses trust quickly.

## Support offline and partial failure

Show what can continue without a network and what must wait. Give people a way to retry, export or contact support. The [desktop service](/services#desktop) starts from these real operating conditions.
