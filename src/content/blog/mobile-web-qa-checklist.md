Quality assurance is the evidence that a release behaves as intended under realistic conditions. It is not a final click-through performed after the deadline.

## Start with critical workflows

List the actions that create value and the actions that create risk. Test happy paths, validation, retries, permissions, empty states and destructive actions. Keep the expected result beside each test.

## Cover real environments

For web, test browsers, keyboard access, zoom, slow networks and responsive widths. For mobile, test supported OS versions, interrupted connectivity, permissions, backgrounding and different screen sizes. Use the devices your audience actually owns.

## Check the edges

Try duplicate taps, expired sessions, malformed input, partial uploads and a service that is temporarily unavailable. Recovery behaviour is part of product quality.

## Automate the stable core

Automate repeatable unit, integration and smoke tests. Keep exploratory sessions for questions automation cannot answer, such as whether a first-time user understands the interface.

## Ship with a release record

Record build version, test evidence, known issues, rollback steps and ownership. This keeps a small team calm when a real issue appears after launch. [See our QA service](/services#qa).
